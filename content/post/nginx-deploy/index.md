“前端调用后端，应该使用内网域名还是公网域名？”

这个问题容易把“前端”当成一个固定位置。实际上，运行在浏览器里的 JavaScript、执行 SSR 的 Web Server、移动客户端和第三方系统都可能被称为前端，它们却处在完全不同的网络与信任边界中。

域名不是起点。先确定请求从哪里发出、经过哪些入口、在哪一层完成身份校验，域名选择通常会自然出现。

## 先区分代码归属和请求来源

同一个页面包含两段完全不同的执行链路：

```text
页面加载： Browser ──public──> CDN / Nginx

API 调用： Browser ──public──> API ingress ──private──> Backend
```

即使浏览器中的代码由“前端团队”编写，请求仍然来自用户网络。浏览器无法直接访问数据中心或 VPC 中的私有地址。`fetch("/api/orders")` 看起来没有独立 API 域名，只是因为公网入口使用同源路径接住了请求：

```nginx
location /api/ {
    proxy_pass http://orders.internal:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

外部请求仍然存在，只是公开边界从 `api.example.com` 变成了 `example.com/api`。

真正可以直接使用内网域名的，是运行在受控网络里的服务端组件：

```text
Browser ──public──> BFF / SSR ──private──> Backend
```

因此，第一个问题应该是：**发起连接的是浏览器，还是服务器？**

## 三种常见边界

### 同源入口：`example.com/api`

浏览器只接触一个公开域名，Nginx 或网关根据路径转发。它天然规避浏览器跨域配置，适合 Web 单体入口和规模较小的系统。

代价也很明确：前端资源与 API 共用故障域、证书和流量策略，路由规则会逐渐承担网关职责。

### 独立 API：`api.example.com`

浏览器、移动端和第三方都从公开 API 入口进入。路由、限流、鉴权和可观测性更容易独立演进，但必须显式处理 CORS、Cookie 域、CSRF 与客户端版本兼容。

“独立域名”并不会自动带来安全性。安全来自入口之后的身份验证、授权、速率限制和后端网络隔离。

### BFF：公开协议在边缘终止

浏览器只调用面向页面的 Backend for Frontend，BFF 再通过私有网络访问内部服务。这能隐藏内部 API 形状，并把多服务聚合、令牌转换和客户端兼容放在边缘。

代价是增加一跳和一个新的状态边界。BFF 如果只是机械转发，价值通常不足以抵消复杂度。

## DNS 不负责 `/api`

另一个常见误区是把 DNS 和反向代理混在一起。

DNS 只把主机名解析为地址：

```text
example.com → 203.0.113.10
```

请求到达该地址后，Nginx 才根据 Host、path、method 等信息选择 upstream：

```text
DNS：这个主机在哪里？
Ingress：这个请求应该交给谁？
Backend：这个调用是否被允许？
```

三层各自回答一个问题。把授权寄托在“使用了内网域名”，或者把路由问题归因于 DNS，都会模糊真正的控制点。

## “不暴露后端”需要更精确

如果浏览器可以调用某个接口，这个接口就已经通过某种公网入口暴露。真正被隐藏的是内部服务地址和拓扑，而不是业务能力本身。

一个较完整的外部入口至少需要考虑：

- TLS 在哪一层终止；
- 用户身份在哪一层建立；
- 路由之前还是之后执行限流；
- 客户端 IP 如何可信地向后传递；
- 超时预算如何在代理和服务之间分配；
- 重试是否会放大非幂等操作；
- 内部服务是否只接受来自入口层的流量。

配置片段只能说明转发关系，不能代替这些决策。

## 用一张决策表结束争论

| 调用方 | 网络位置 | 推荐入口 | 后端地址 |
|---|---|---|---|
| 浏览器 | 不可信公网 | 同源 `/api` 或公开 API 域名 | 对浏览器不可见 |
| 移动端 | 不可信公网 | 公开 API 域名 | 对客户端不可见 |
| 第三方系统 | 外部网络 | 独立公开 API / 专用网关 | 通过入口访问 |
| SSR / BFF | 受控服务网络 | BFF 为公开入口 | 可使用私有服务发现 |
| 内部服务 | VPC / 集群网络 | 内部网关或服务发现 | 私有域名 |

域名方案最终应该能回答一句话：**谁可以从哪里建立连接，谁在什么位置决定它是否有权继续。**
